<Interface>
인터페이스는 일종의 '리모컨'으로 생각할 수 있음.
인터페이스라는 리모컨으로 연결된 '장치'들을 조작.

interface가 가질 수 있는 멤버
-> public 상수 필드 : 인터페이스에 선언된 필드는 모두 public static final 특성을 갖기 때문에 자동으로 상수가 됨. 
                     상수명은 대문자로 하되, 서로 다른 단어로 구성된 경우 언더바(_)로 연결하는 것이 관례.
-> public 추상 메소드 : 구현 클래스는 인터페이스의 모든 추상 메소드를 오버라이딩 해야 됨. 기본적으로 public의 
                       접근 제한자를 가짐.
-> public 디폴트 메소드 : 인스턴스 메소드로써 구현 객체가 있어야만 호출 가능. 구현객체에서 오버라이딩 가능.
-> public 정적 메소드 : 구현 객체가 없어도 인터페이스만으로 호출 가능.
-> private 메소드 : 인터페이스 내부에서만 호출 가능함. 목적은 중복 코드를 줄이기 위해 사용함.
-> private 정적 메소드

<다중 인터페이스 구현>
하나의 객체가 여러개의 인터페이스를 구현할 수 있는데, 어떤 리모컨을 사용하느냐에 따라 호출할 수 있는 메소드가 달라짐.

<인터페이스 상속>
자식 인터페이스의 구현 객체는 자식 인터페이스의 메소드 뿐만 아니라 당연히 부모 인터페이스의 모든 추상 메소드를 재정의 해야됨. 따라서 자식 인터페이스의 구현 객체는 자식 인터페이스 뿐만 아니라 부모 인터페이스에도 대입 될 수 있음.
-> 부모 인터페이스에 대입 된 자식 인터페이스는 부모 인터페이스에 존재하는 메소드만 호출 가능함.

<자동 타입 변환>
조건 : 부모인터페이스 변수 = 자식 인터페이스의 구현 객체
결과 : 자식 인터페이스의 구현 객체가 부모인터페이스 변수에 담기면서, 부모인터페이스의 추상 메소드 구현 가능.

<강제 타입 변환>
조건 : 구현클래스 변수 = (구현클래스) 인터페이스변수
결과 : 인터페이스 변수에 담긴 구현객체는 인터페이스변수를 구현하는 객체로써 인터페이스에서 정의된 추상 메소드만
       호출 가능했지만, 강제타입변환을 하면 구현객체가 아닌 하나의 독립적인 클래스로써 해당 클래스에 정의된 모든
       메소드와 필드에 접근 가능해짐.

<인터페이스의 다형성>
클래스의 상속을 통해 구현하던 다형성을 인터페이스를 통해 구현 가능.
1. 필드의 다형성
2. 매개변수의 다형성
여러 종류의 객체를 바꿔가면서 필드나 매개변수에 대입해야 되는 경우, 각각의 타입으로 받을 수 없으므로, 
하나의 인터페이스 타입으로 선언을 한 후 해당 인터페이스를 구현하는 객체를 대입하는 방식으로 다형성 구현 가능.

<객체 타입 확인>
vehicle instanceof Bus 코드를 통해 vehicle 변수에 대입 된 구현객체가 원래 어떤 클래스 인지를 파악 가능.
vehicle에 대입된 변수가 Bus 클래스라면 true를, 아니라면 false를 반환함.

<봉인된 인터페이스>
sealed 코드를 통해 더이상 상속이 불가능한 인터페이스를 정의할 수 있음. permits 된 인터페이스에서는
non-sealed 코드를 통해 다시 상속이 가능하도록 하거나 sealed 키워드를 통해 또 다른 봉인 인터페이스로 선언해야 됨.
