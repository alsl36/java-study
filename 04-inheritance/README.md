자식 클래스가 생성될 때는 부모 클래스도 자동으로 생성됨. 이 것이 가능한 이유는 자식 클래스의 생성자에 super()라는 함수가 컴파일 과정에서 자동으로 추가되기 때문인데, super() 함수는 부모 클래스의 생성자를 호출하는 함수임.

메소드가 오버라이딩 되면 부모의 메소드는 숨겨지고, 자식 메소드가 우선적으로 사용됨.
(1. 부모 메소드의 선언부와 동일해야 된다.)
(2. 접근 제한을 더 강하게 오버라이딩 할 수 없다.)
(3. 새로운 예외를 throws할 수 없다.)

final 필드 : 초기값 설정 후 변경 불가능
final 클래스 : 상속 불가능한 클래스
final 메소드 : 오버라이딩 불가능한 메소드

protected 접근 제한자 : 같은 패키지에서 접근 가능 + 자식 클래스라면 다른 클래스에서도 접근 가능

<자동타입변환>
조건 : 부모타입 변수 = 자식타입객체;
결과 : 자식타입객체가 부모타입 변수 안에 담기게 됨.
결과 : 부모클래스에서 선언된 메소드에만 접근이 가능하지만, 자식클래스에서 오버라이딩을 했다면 오버라이딩 된 메소드가 실행됨.

<강제타입변환>
조건 : 자식타입 변수 = (자식타입) 부모타입객체;
조건 : 부모타입으로 자동 변환 된 (원래자식객체였던) 객체만 강제타입변환 가능.
이유 : 부모타입으로 자동 변환 된 자식객체는 부모클래스에 정의된 메소드만 호출 가능하기에 자식 클래스에 새로 정의된 메소드 호출하기 위해
결과 : 자식클래스에 새롭게 정의된 필드와 메소드에 접근 및 호출 가능해짐.

1. 필드에서의 다형성 
2. 매개변수에서의 다형성
필드나 매개변수에 서로 다른 종류의 객체를 바꿔가면서 전달해야되는 경우 여러 종류의 객체를 받을 수 있는 타입으로써 부모 클래스를 생성함.
이렇게 실제로는 부모 클래스가 필요 없지만 자식 클래스들을 담을 수 있는 껍데기 역할로써 필요한 경우가 많은데, 이 때 사용하는 것이 '추상 클래스'

<객체타입확인>
자동타입변환 된 객체가 원래 어떤 클래스의 객체인 지를 확인할 수 있는 방법.
parent instanceof Child 코드를 호출하면 parent 변수 내의 객체가 Child 클래스 인지를 판단하여 boolean 타입의 리턴값 반환됨.

실체 클래스 : 객체를 생성할 수 있는 클래스
추상 클래스 : 객체를 생성할 수 없는 클래스 (껍데기 역할만 수행)
-> 추상 클래스를 사용하는 경우 부모 클래스의 메소드 역시 껍데기 역할만 수행하는 경우가 많은데, 이 경우 메소드만 존재하고 해당 메소드 내에는
   아무 내용이 없는 추상 메소드를 생성할 수 있음. 추상 메소드를 정의한 경우 자식 클래스에서 반드시 오버라이딩을 해줘야 됨.

<봉인된 클래스>
public sealed class Person permits Employee, Manager { ... }
이렇게 sealed 코드를 통해 Person 클래스를 permits 된 클래스에만 상속이 가능하도록 제한 가능.

public final class Employee extends Person { ... }
public non-sealed class Manager extends Person { ... }
permits 된 클래스는 다음과 같이 final 클래스나 non-sealed 클래스 2개가 될 수 있는데, 
final 클래스인 Employee 는 더이상 상속이 불가능한 클래스가 되고, non-sealed 클래스인 Manager 는 상속이 자유로워진 클래스가 됨.
